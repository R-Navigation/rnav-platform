# RNAV Console 业务完善设计

## 1. 背景与目标

统一平台已经完成公开网站、监控、实验室资产、采购、统一登录和基础权限框架的生产迁移，但以下 console 页面仍是占位状态：

- `/console/profile`
- `/console/media`
- `/console/users`
- `/console/permissions`
- `/console/settings`

本设计的目标是补齐账号生命周期、成员资料、权限配置、媒体资源和系统设置，使 RNAV 平台成为可长期维护的完整业务系统。新增能力继续遵守一个代码库、一个 PostgreSQL 数据库、一个 Node 服务和一个 nginx 应用入口的架构。

## 2. 交付顺序

功能分为两个可独立上线和回滚的阶段。

### 2.1 第一阶段：账号闭环

第一阶段包含：

- 个人资料查看与编辑
- 公开成员资料自主展示控制
- 修改密码
- 首次登录强制改密
- 用户创建、停用、恢复和密码重置
- 岗位权限模板与单项权限微调
- super 保护规则
- 会话撤销和审计日志

第一阶段上线后，现有成员临时密码账号统一标记为首次登录必须改密。

### 2.2 第二阶段：媒体与系统设置

第二阶段包含：

- 腾讯云 COS 上传
- 图片上传前裁剪、缩放和压缩
- PDF 上传
- 资源搜索、选择、替换和引用追踪
- 资源回收站与永久删除
- 全局业务设置
- 维护模式

## 3. 业务域边界

### 3.1 Account 域

Account 域负责当前登录成员自己的资料和安全操作：

- 读取和编辑内部个人资料
- 选择可公开字段并立即同步游客成员页
- 修改当前密码
- 完成首次登录强制改密
- 修改密码后撤销其他会话

### 3.2 User Admin 域

User Admin 域负责账号生命周期：

- 创建并关联成员账号
- 生成一次性临时密码
- 停用和恢复账号
- 管理员重置临时密码
- 查看账号状态、身份和最近登录时间
- 强制撤销目标账号会话

### 3.3 Permission Admin 域

Permission Admin 域负责岗位模板和授权来源：

- 维护系统内置岗位模板
- 为用户关联一个或多个岗位模板
- 在模板基础上增加单项授权
- 在模板基础上增加单项撤销
- 计算并展示最终有效权限、来源和最终身份
- 权限变化后立即撤销目标账号旧会话

### 3.4 Media 域

Media 域负责 COS 对象和数据库资源记录的一致性：

- 上传图片和 PDF
- 使用已有资源
- 上传前处理图片
- 查询业务引用
- 替换业务资源引用
- 回收、恢复和永久删除资源

### 3.5 System Settings 域

System Settings 域只管理可安全存入数据库的业务配置。数据库连接、COS 密钥、session secret、password pepper 和 device token pepper 等敏感值继续只保存在服务器环境文件中。

## 4. 第一阶段数据设计

### 4.1 用户账号

`users` 增加：

- `must_change_password boolean NOT NULL DEFAULT false`
- `password_changed_at timestamptz`
- `created_source text NOT NULL DEFAULT 'admin'`

用户名创建后不可修改。显示名称、状态和权限可以修改。

管理员创建或重置账号时生成一次性临时密码，并设置 `must_change_password=true`。系统不能读取或找回原密码。临时密码只在创建或重置成功结果中显示一次，关闭后不能再次查看。

### 4.2 成员资料

`user_profiles` 是内部成员资料的权威来源，并扩展以下字段：

- 邮箱
- 手机号
- 中英文个人简介
- 中英文研究方向
- 个人主页
- GitHub
- 公开字段集合 `public_fields`
- 乐观并发版本号

成员可控制以下信息是否同步到公开成员页：

- 头像
- 中英文姓名
- 职称
- 个人简介
- 研究方向
- 邮箱
- 个人主页
- GitHub

手机号只允许内部使用，不能加入公开字段集合。成员可以关闭中英文姓名的公开展示；当两个姓名字段都关闭时，游客成员页使用“课题组成员 / Lab Member”作为中性占位名称，同时保留成员类别。成员关闭其他可选字段后，公开记录清空对应展示值。

保存个人资料时，在同一个数据库事务中更新 `user_profiles` 和已关联的 `team_members`。资料更新无需管理员审核，保存后立即生效。

### 4.3 权限模板

新增：

- `permission_templates`
- `permission_template_permissions`
- `user_permission_templates`
- 用户单项权限覆盖记录

内置模板包括：

- 普通成员
- 官网编辑
- 资产管理员
- 监控管理员
- 采购审批
- 采购执行
- 用户管理员

最终权限按以下顺序计算：

1. normal 基础权限
2. 岗位模板授予
3. 用户单项授权
4. 用户单项撤销岗位模板或进阶授权

`super` 始终获得所有已知权限，不通过模板计算。`plus` 仍是拥有任一进阶权限的 normal 用户自动计算出的展示身份，不写入数据库基础身份字段。

normal 的基础权限不可通过模板或单项撤销移除。失去内部访问资格应通过停用账号处理，不能制造缺少基础能力的半有效 normal 账号。

API 必须返回每项最终权限的来源，使后台能够区分基础、模板、单项授权和单项撤销。

## 5. 第一阶段业务规则

### 5.1 新增成员账号

管理员创建账号时填写：

- 用户名
- 中英文姓名
- 成员类别
- 邮箱

系统自动：

- 创建 `users`
- 创建并关联 `user_profiles`
- 创建或关联公开 `team_members`
- 授予普通成员基础权限
- 生成一次性临时密码
- 设置首次登录强制改密
- 写入审计日志

### 5.2 密码与会话

密码至少 12 位，并包含：

- 大写字母
- 小写字母
- 数字
- 特殊字符

成员修改密码必须输入当前密码。管理员重置密码不需要知道原密码，但只能获得一次性临时密码。

以下操作撤销目标账号现有会话：

- 修改密码
- 管理员重置密码
- 停用账号
- 权限发生变化

成员自己修改密码时保留新创建的当前会话或立即建立新会话，其他会话全部删除。

### 5.3 首次登录限制

`must_change_password=true` 的账号登录后只能：

- 读取必要的当前会话信息
- 打开账号安全页面
- 修改密码
- 退出登录

其他 console API 返回明确的 `PASSWORD_CHANGE_REQUIRED` 错误。前端统一跳转 `/console/profile?section=security`。

### 5.4 super 保护

- 只有 super 可以创建、提升、降级或停用其他 super。
- 非 super 权限管理员不能修改 super。
- 用户不能停用自己。
- 用户不能移除自己的关键管理能力。
- 系统必须始终至少保留一个 active super。
- super 相关检查必须在数据库事务中加锁，避免并发操作绕过最后一个 super 保护。

## 6. 第一阶段界面设计

### 6.1 `/console/profile`

页面使用三个页签：

- 个人资料
- 公开展示
- 账号安全

公开展示页提供字段开关和公开成员页预览。保存后显示清晰的成功状态；版本冲突时要求重新加载，不静默覆盖其他修改。

账号安全页提供当前密码、新密码和确认密码。首次登录用户默认进入该页，其他导航不可使用，直到改密成功。

### 6.2 `/console/users`

页面包含：

- 搜索
- normal、plus、super 身份筛选
- active、disabled、invited 状态筛选
- 用户表格
- 创建账号抽屉或对话框
- 停用和恢复
- 重置临时密码
- 查看账号详情

临时密码结果使用一次性结果对话框，不写入日志、不提供再次查看按钮。

### 6.3 `/console/permissions`

左侧选择用户，右侧显示：

- 当前基础身份
- 岗位模板
- 单项权限微调
- 最终权限来源
- 最终 normal、plus 或 super 身份
- 最终可用 console 模块

保存前显示变化摘要。保存成功后提示目标用户旧会话已失效。

## 7. 第二阶段媒体设计

### 7.1 资源模型

每次确认上传只产生一份 COS 对象和一条 `media_assets` 记录。不生成缩略图或派生版本，也不额外保存上传前原图。

需要另一种尺寸或比例时，用户可以：

- 重新上传一个新资源
- 直接复用同一个已有资源

### 7.2 图片处理

上传确认前，浏览器提供：

- 裁剪
- 缩放
- 压缩质量调整
- 结果尺寸和文件大小预览
- 取消并恢复当前业务引用

浏览器处理后的最终文件作为唯一资源上传。服务端仍校验最终 MIME、扩展名、尺寸、20 MB 上限和 SHA-256。

### 7.3 统一资源控件

所有需要图片或 PDF 的业务表单使用统一资源控件，包括：

- 成员头像
- 官网内容图片
- 新闻封面
- 研究成果图片和 PDF
- 实验平台图片
- 后续新增的媒体字段

控件提供：

- 选择已有资源
- 直接上传
- 替换
- 清除引用
- 查看资源详情
- 图片裁剪与尺寸调整

不再要求业务用户手工填写资源 URL。

### 7.4 替换与自动回收

替换资源的流程：

1. 上传新资源或选择已有资源。
2. 新资源准备成功后，在数据库事务中替换业务引用。
3. 事务提交后重新计算旧资源引用。
4. 旧资源没有任何业务引用时，自动移入回收站。
5. 旧资源仍被其他业务引用时继续保留。

裁剪取消、上传失败或引用更新失败时，原业务引用保持不变，旧资源不能进入回收站。

### 7.5 引用追踪

媒体服务统一查询所有已知引用，包括结构化外键和页面 JSON 中的资源 ID。引用查询必须返回业务模块和记录名称。

有引用的资源不能手动移入回收站。新业务增加媒体字段时，必须同时注册引用查询规则。

### 7.6 回收站

- 未引用资源可手动移入回收站。
- 替换后无引用的旧资源自动进入回收站。
- 资源进入回收站后保留 3 天。
- 3 天内可以恢复。
- 满 3 天且仍无引用时允许永久删除。
- 永久删除必须先删除 COS 对象，成功后再删除数据库记录。
- COS 删除失败时保留数据库记录并记录重试状态和审计日志。

## 8. 第二阶段系统设置设计

系统设置分组：

- 站点：课题组名称、联系方式、备案号
- 区域：默认语言、时区
- 安全：会话有效期
- 监控：离线判定时间
- 采购：采购单号前缀和基础流程开关
- 媒体：上传大小和允许类型
- 维护：维护模式和维护提示

设置采用版本号乐观并发控制。后台只能显示 COS 等外部服务是否已配置，不能返回任何密钥值。

维护模式只影响游客页面；以下接口始终可用：

- 登录和退出
- console
- 健康检查
- 设备 ingest

super 可以预览维护页面并关闭维护模式。

## 9. API 与安全规则

- Express 服务负责全部业务规则和数据库写入。
- Next.js API route 只作为浏览器代理，不能重新实现权限判断。
- 所有写操作必须执行登录校验、细粒度权限校验和同源校验。
- 用户输入使用严格 schema，拒绝未知字段和超限数据。
- 登录和密码修改接口增加按账号和来源地址的速率限制。
- 密码、临时密码、session token、COS 密钥和 pepper 不进入审计详情。
- 所有敏感操作写入 `audit_logs`，包括账号、密码、资料公开范围、权限、媒体删除和系统设置修改。

## 10. 错误处理与事务

- 账号创建、成员资料同步、权限修改和媒体引用替换使用数据库事务。
- super 保护使用行锁或事务级锁。
- 并发资料和系统设置保存使用版本冲突响应。
- COS 上传成功但数据库写入失败时，服务执行补偿删除；补偿失败时记录待清理对象。
- 永久删除不允许数据库记录先于 COS 对象消失。
- API 返回稳定错误码，前端根据错误码显示可操作提示。

## 11. 测试与验收

### 11.1 第一阶段

- 个人资料读写和公开字段同步测试
- 手机号永不公开测试
- 首次登录 API 限制测试
- 修改密码和重置密码测试
- 会话撤销测试
- 用户创建、停用、恢复测试
- 最后一个 active super 保护测试
- 自我停用和自我撤权保护测试
- 岗位模板、单项授权、单项撤销和来源计算测试
- normal、plus、super console 模块测试
- 浏览器端表单、冲突、一次性密码和权限预览测试

### 11.2 第二阶段

- MIME、扩展名、尺寸和大小校验测试
- 上传补偿测试
- 资源引用追踪测试
- 替换后有引用和无引用的分支测试
- 3 天回收时间测试
- COS 删除失败重试测试
- 设置并发冲突测试
- 维护模式公开和内部路由测试
- 图片裁剪、缩放、取消和替换浏览器测试

### 11.3 上线验收

每个阶段必须执行：

- 本地测试、lint 和 production build
- staging schema migration
- 生产数据库备份
- migration 与数据核验
- normal、plus、super 真实账号验收
- 游客数据边界验收
- 桌面与移动端浏览器验收
- systemd、nginx 和日志验收
- 明确的回滚步骤

## 12. 非目标

本轮不包含：

- 邮箱自助找回密码
- 手机短信找回密码
- 第三方 OAuth 或学校统一认证
- 图片派生版本和自动缩略图
- 在后台查看或修改 COS 密钥、数据库密码或 pepper
- 多组织或多课题组租户模型
