# Public UI 4.2 分阶段验收

## 范围与约束

本轮严格限定为 4.1 之上的视觉层升级：不重做信息架构，不改变公开路由、双语、CMS 数据来源、公开 API、COS 安全代理、设施隐私投影、SEO、空态或 Console 权限。未新增数据库表或迁移，也未写入、导入、清理生产数据。

参考图只用于构图和层次对照。图中的合成机器人、山景、论文、人物、统计与地址均未作为生产事实或素材使用；页面继续消费现有正式公开数据，无正式论文/新闻时保留真实空态。

## Phase 0 — 生产基线审计

- 检查当前 HEAD、4.1 验收记录、七个公开页面、公共壳、旧 `PageHero`、实际使用的 `ui4/Hero`、`Media`、页面 DTO 与图片链路。
- 确认 4.1 Hero 的根因是容器内 45/55 网格；本轮改实际使用的共享 primitive，不修改未使用的旧包装器。
- 已有图片 JSON 支持 `positionX`、`positionY`、`zoom`，因此直接复用，不需要数据库变更。
- 保留固定 COS 桶和 LIESMARS 域名策略、公开 DTO 白名单、图片代理尺寸/并发限制和失败回退。

## Phase 1 — 共享 Hero 4.2

- `Hero` 支持 `fullBleed`、`editorialSplit`、`featureShowcase` 三种组合。
- 图片脱离内容容器，绝对定位覆盖整个 Hero，统一 `cover`；桌面与手机分别支持默认焦点位。
- CMS 已设置的焦点优先于页面预设，数值在展示层限制为 0–100%，缩放限制为 1–2，避免异常 JSON 破坏页面。
- 支持可选真实视觉叠加槽与公共信息浮层；手机自动改单列、取消脆弱定位。
- 后台页面顶部图片编辑器增加水平焦点、垂直焦点和缩放控制，预览实时同步，继续通过原页面 JSON 保存。

## Phase 2 — 首页与实验平台

- 首页使用 `fullBleed`，真实公开数据生成研究方向、公开平台与成员档案快速入口；底部联系 CTA 使用图片基底。
- 实验平台使用 `featureShowcase`，Hero 首选后台首图、其次重点平台真实照片；浮层只显示公开平台类别和公开设备数量。
- 重点平台改为图片、介绍卡和公开配置面板的叠层关系；未读取或展示资产编号、序列号、库位、领用人、采购信息等内部字段。
- 逐页截图对照 `concepts/full-pages/01_homepage.png` 与 `04_facilities.png` 后进入下一阶段。

## Phase 3 — 研究方向、论文成果与新闻

- 三页使用 `editorialSplit`，背景仍为完整覆盖图，不再是右侧圆角图片卡。
- 研究方向保留方向卡、论文关联与应用场景结构。
- 重点论文使用图像基底与前置内容卡；筛选、分类栏和归档保持扁平清晰。
- 重点新闻使用图像基底与摘要卡叠层；当前无正式新闻时，同一版位显示真实空态而非示意新闻。
- 逐页截图对照对应 `concepts/full-pages/02`、`03`、`06` 后进入下一阶段。

## Phase 4 — 团队与联系

- 团队使用 `fullBleed`；遵循用户对 4.1 的最终要求，导师、博士后、博士、硕士、本科、校友仍纵向排列，各组内部卡片网格，不恢复概念图的三组并排或重复 PI 区。
- 团队底部加入图片层 CTA，满足 4.2 的重点叠层要求；真实集体工作照尚未配置时使用官方校园风景回退。
- 联系页使用 `fullBleed`；主要联系卡覆盖校园照片边缘，位置区继续采用图片＋信息卡，准确地址仍以现有高德链接为准。
- 逐页截图对照 `concepts/full-pages/05_team.png` 与 `07_contact.png`，其中团队结构以用户后续明确反馈优先。

## Phase 5 — 截图与质量门

- 七页均在 1440×900、1280×800、1024×768、768×1024、390×844 五个要求视口完成截图，共 35 个页面/视口组合。
- 每个视口均检查 `scrollWidth === clientWidth`，未发现横向页面溢出；Hero 实测高度符合页面预设。
- 390×844 七页逐页人工检查；首页英文长标题 `Safe Resilient Navigation and Embodied Intelligence` 完整换行，仍无横向溢出。
- 桌面叠层在手机全部取消负边距或改为纵向衔接；图片使用 `cover`，无 letterbox；CMS 焦点位在桌面和手机都生效。
- 全局 `focus-visible`、44px 交互目标和 `prefers-reduced-motion` 规则继续生效。Hero 图片为 `loading=eager` / `fetchpriority=high`，正文图片继续懒加载。
- 浏览器未发现运行时 error；Next 开发模式对同一图片 URL 在 Hero 与正文重复出现给出 LCP 提示，但实际 Hero DOM 已核对为 eager/high，生产构建不受影响。
- 回归测试 402 项全部通过：Web 98、Server 277、scripts 27；新增焦点元数据边界测试。
- `npm run lint` 通过，0 error；仍为 4 项既有后台原生 `img` warning，本轮公开页未新增 lint warning。
- `npm run build` 通过：Next 16.3.5 的 28 个路由完成发布构建，Server TypeScript 编译通过。

## 建议后续替换的真实生产素材

这些不是上线阻塞项，后台现在可直接上传并调焦：

1. 团队成员页：真实集体工作照或实验现场横图，替换官方校园回退。
2. 研究方向页：包含真实机器人与环境语义的横向研究现场图。
3. 论文成果页：正式重点论文发布后配置对应论文视觉图。
4. 新闻动态页：正式活动发布后配置真实活动主图。
5. 联系页：实验室所在楼宇或室内环境实拍；地址仍以公开地图链接为准。
